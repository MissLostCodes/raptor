\title{\textbf{When Does Adaptive Leaf Granularity Help Hierarchical
Retrieval?}\\[2pt]
\large A Training-Free Harness and a Negative Result for Cheap Density Features}

\author{Shagun Gupta\\\small Working draft --- \today}
\date{}

\begin{document}
\maketitle

\begin{abstract}
RAPTOR-style hierarchical retrieval builds a tree by recursively clustering and
summarizing \emph{leaf chunks}, but inherits a naive fixed-size leaf chunker that
ignores how documents differ in information density. We ask whether per-document
leaf granularity can be set \emph{cheaply} and \emph{without training a model},
and whether doing so beats a single well-tuned fixed leaf size inside an
otherwise-frozen pipeline. We make two contributions of method and one of
result. (i) We build a reusable, \emph{no-LLM} evaluation harness for leaf
granularity in hierarchical RAG: an oracle leaf-size sweep scored by a
gold-evidence token-coverage proxy. (ii) We frame chunking control as two cheap
deterministic axes---a \emph{structure score} that decides \emph{where} to cut
and a \emph{density score} that decides \emph{how big} each leaf is. (iii) On
QASPER (50 papers, 171 answerable questions) we find that per-document optimal
leaf size is genuinely heterogeneous, leaving real headroom---a per-document
oracle beats the best single fixed size by $+9.8\%$ relative gold-evidence
coverage (\textbf{H1}). However, cheap deterministic density features
\emph{fail} to capture that headroom: used to size leaves, the
selected-feature map beats a tuned global fixed size in only $7/50$ random
train/test splits (mean $0.704$ vs.\ $0.729$), and a learned regressor on the
same features also loses (\textbf{H2}). We report this as an honest negative
result: the common ``smaller chunks for denser text'' heuristic is
\emph{not supported} at the hierarchical-leaf level; a single tuned global leaf
size is a strong baseline. We then ask whether \emph{causally-motivated}
locality features---semantic-segment size, paragraph length, compressibility---do
better, and find they do not (best $|\rho|=0.25$, all below the surface best);
strikingly, even a \emph{label-derived} diagnostic (the gold-evidence span length)
is uncorrelated with optimal size ($\rho\approx0$), so the optimum is not an
exploitable function of \emph{any} document-intrinsic property we measured. The
refutation generalizes: on a second corpus (QuALITY, $30$ articles, an
answer-recall proxy) the best cheap feature reaches only $|\rho|=0.40$ and a
selected-feature size map ties---but does not beat---a tuned fixed size
(win-rate $52\%$), so it is not QASPER-specific. A QuALITY control further
confirms the structure axis does no harm on unstructured prose (structure-routing
rate $0$). Finally, scaling to the \emph{full} QASPER test split ($416$ papers,
$1{,}352$ questions), a held-out nested-oracle decomposition localizes the residual
headroom: a per-document leaf-size oracle \emph{underperforms} a single global size
out-of-sample ($-0.045$ coverage, $95\%$ band $[-0.060,-0.028]$), and essentially
all exploitable headroom is \emph{within-document}---it varies question-to-question
($O_4{-}O_1={+}0.135$) and concentrates in multi-evidence aggregation questions. The
negative result is therefore structural: the signal a leaf-size policy would need
lives below the document level, where no document-intrinsic feature can reach it.
\end{abstract}

% ----------------------------------------------------------------------------
\section{Introduction}
\label{sec:intro}

Chunking is a known lever for retrieval-augmented generation (RAG), but its
interaction with \emph{hierarchical} retrieval is under-studied. RAPTOR
\cite{sarthi2024raptor} is agnostic to leaf chunking: it splits a document into
fixed-size leaves ($\approx 100$ tokens), then recursively clusters and
LLM-summarizes them into a tree that is queried by collapsed-tree retrieval. The
leaf chunker is therefore a clean, isolatable variable inside an otherwise-frozen
pipeline---and a fixed leaf size ignores that documents differ in information
density.

The \emph{broad} idea ``adapt chunk size to content'' is not novel. Our specific
question is narrower and, to our knowledge, unoccupied: can per-document leaf
granularity be set by a \emph{cheap, closed-form, training-free} score, and does
that beat a single tuned fixed size for hierarchical-RAG leaves? We answer it with
a deliberately strong methodology---an oracle upper bound, a tuned fixed-size
lower bound, and a learned regressor as a same-features ceiling---so that a
negative answer is informative rather than an artifact of a weak method.

\paragraph{Contributions.}
\begin{enumerate}
  \item A reusable \textbf{training-free, no-LLM harness} (Section~\ref{sec:harness})
  to study leaf granularity in hierarchical RAG: an oracle leaf-size sweep scored
  by a gold-evidence token-coverage proxy; resumable and free-tier-friendly.
  \item A \textbf{two-axis decomposition} of chunking control
  (Section~\ref{sec:method}): a structure score (\emph{where} to cut) and a
  density score (\emph{how big}), each deterministic and LLM-free.
  \item An empirical \textbf{characterization and refutation}
  (Sections~\ref{sec:h1}--\ref{sec:h2}): per-document optimal leaf size is
  heterogeneous with real oracle headroom (\textbf{H1}), but cheap density
  features---and a learned regressor over them---fail to capture it (\textbf{H2}).
  We further test \emph{causally-motivated} semantic-locality features and a
  \emph{label-derived} target diagnostic, both of which also fail
  (Section~\ref{sec:locality}), strengthening the refutation from ``these surface
  features are weak'' to ``no cheap document-intrinsic property predicts the
  optimum.'' This is a first clean formalization and refutation of the common
  ``denser $\Rightarrow$ smaller chunks'' heuristic for hierarchical-RAG leaves.
\end{enumerate}

% ----------------------------------------------------------------------------
\section{Related Work}
\label{sec:related}

\paragraph{Hierarchical retrieval.} RAPTOR \cite{sarthi2024raptor} is our frozen
backbone; we vary only its leaf chunker.

\paragraph{Adaptive / learned chunk granularity.} Mix-of-Granularity
\cite{mog2024} \emph{learns} a soft router over granularities (a trained model)---
the closest prior art and exactly the ``use a model'' route we avoid as a
contribution. HiChunk \cite{hichunk2025} performs hierarchical structuring with a
\emph{fine-tuned} LLM and query-adaptive granularity. ``Rethinking Chunk Size for
Long-Document Retrieval'' \cite{rethink2025} analyzes chunk size but proposes no
per-document policy. Ekimetrics Adaptive Chunking \cite{ekimetrics} selects a
discrete chunking \emph{method} per document with a classifier over flat
retrieval; it does not set a continuous \emph{granularity} and trains a selector.

\paragraph{Our niche.} A \emph{cheap, closed-form, training-free} score that sets
\emph{per-section leaf granularity} in a \emph{hierarchical tree}, validated
against an oracle. ``Training-free'' separates us from the learned MoG/HiChunk;
the continuous size, the hierarchical-leaf target, and oracle calibration
separate us from Ekimetrics. The two-axis decomposition (structure$\to$boundary,
density$\to$size) is, to our knowledge, not stated cleanly in prior work.
\emph{This paper reports that the density axis, in its cheap training-free form,
does not pay off}---which is itself the result.

\section{A Training-Free Harness for Leaf Granularity}
\label{sec:harness}

Measuring ``which leaf size is best for this document'' end-to-end requires an
LLM per (document, size) cell---prohibitive on a free-tier budget. We instead
use a cheap retrieval proxy that needs \emph{no} LLM.

\paragraph{Oracle leaf-size sweep.} For each document $d$ and each candidate leaf
size $S \in \{50,100,150,200,300,400\}$ tokens, we split $d$ into $S$-token
leaves, embed them with a fixed SBERT model
(\texttt{multi-qa-mpnet-base-cos-v1}), index with FAISS, and retrieve under a
fixed $2000$-token budget for every question of $d$.

\paragraph{Gold-evidence coverage proxy.} We score retrieval by
\emph{gold-evidence coverage}: the fraction of a question's gold-evidence
paragraphs whose tokens are recalled (token-recall $\ge 0.8$) within the
retrieved context. This replaces exact-paragraph evidence-$F_1$, which is
ill-defined when chunk boundaries differ from gold-paragraph boundaries. We
define the per-document optimal size as
$\hat S(d) = \arg\max_S \mathrm{cov}(d,S)$.

The sweep is deterministic, resumable, and Drive-cached; the QASPER run produces
$50 \times 6 = 300$ \texttt{(doc,size)} records with no LLM call. This is what
makes a rigorous negative result affordable.

\section{Method: Two-Axis Chunking Control}
\label{sec:method}

We decompose leaf chunking into two cheap deterministic axes; everything below is
LLM-free at inference.

\paragraph{Axis 1 --- structure score (where to cut).} A deterministic
$\texttt{structure\_score}(d)\in[0,1]$ from surface features (numbered / markdown
/ ALL-CAPS / keyword headings, a generic Title-Case heading detector, TOC-like
regions, inter-heading spacing regularity). A document scoring above a threshold
$\tau$ is routed to a structure-aware chunker (boundaries at headings); otherwise
it falls back to token chunking. This is the Adaptive Hybrid Chunking (AHC) route.

\paragraph{Axis 2 --- density score (how big).} A deterministic
$\texttt{density\_score}(d) = (\rho \in [0,1], \mathbf{f})$ from six surface
features $\mathbf{f}$: mean sentence length, type--token ratio, numeral/symbol
density, mean word length, list-marker density, and non-stopword ratio. A
calibrated map $S = a + b\,f$ turns one chosen feature into a leaf-token budget.

\paragraph{Calibration, not learning.} Rather than assume a direction (``denser
$\Rightarrow$ smaller''), we \emph{calibrate} the density$\to$size map against the
oracle sweep of Section~\ref{sec:harness}. On a training split we rank features by
$|\text{Spearman}|$ against $\hat S(d)$, select the single strongest feature, and
fit a two-parameter closed form $S = a + b\,f$ (no test-set tuning). We compare
this training-free map against (a) the best global fixed size, (b) a learned
$6$-feature linear regressor (same features, a ceiling for ``what these features
can do''), and (c) the per-document oracle (an upper bound).

\section{Experimental Setup}
\label{sec:setup}

\textbf{Data.} QASPER (scientific papers); $50$ papers / $171$ answerable
(gold-evidence) questions. \textbf{Embedder/reader.}
\texttt{multi-qa-mpnet-base-cos-v1} SBERT; \texttt{gpt-oss-120b} (free tier) where
an LLM is used. \textbf{Proxy metric.} gold-evidence token-coverage
($\ge 0.8$ recall). \textbf{Protocol.} $50$ random $70/30$ train/test splits;
we report mean$\pm$std TEST coverage per policy, the win-rate of the selected
feature over the best global fixed size, and feature-selection stability.
\textbf{Controls.} Only the chunker varies; embeddings, clustering, retrieval
budget, and reader are frozen across arms. Results are within-pipeline
(arm-vs-arm), not leaderboard numbers.

\section{H1: Leaf Size Matters and the Optimum is Heterogeneous (PASS)}
\label{sec:h1}

The best single fixed size is $200$ tokens at coverage $0.7362$; the per-document

\textbf{relative} gold-evidence coverage left on the table by any fixed size. The

\section{H2: Cheap Density Features Do Not Capture the Headroom (FAIL)}

\section{Is the Estimator Broken? A Positive Control and Power Analysis}
\label{sec:power}

A negative result invites two objections: the calibration is buggy, or QASPER
simply has too few questions per document ($\approx 3.4$) for the per-document
optimal-size label to be estimable. We rule out both with a synthetic positive
control (\texttt{experiments/signal\_recovery\_power.py}; fully offline). We
\emph{plant} the signal $\hat S = 373 - 926\cdot\text{TTR}$ (the very line our
method fits on QASPER), give each synthetic document a tent-shaped coverage curve
peaking at its planted optimum, and sample it with $Q$ noisy per-question
observations (per-question noise $\sigma_q$, so label noise shrinks as
$\sigma_q/\sqrt{Q}$). We then run the \emph{same} calibration recipe and measure
the recovered Spearman and the win-rate over fixed.

\paragraph{The method is not broken.} With a planted signal present, recovery
improves monotonically with evidence: at $\sigma_q{=}0.25$ the win-rate climbs from
$34\%$ at $Q{=}3$ to $\mathbf{95\%}$ at $Q{=}100$ (recovered $|\rho|$ from $0.22$ to
$0.71$). The estimator captures genuine density$\to$size signal when it exists.

\paragraph{QASPER underperforms even a clean signal of equal strength.} The
win-rate as a function of recovered $|\rho|$ is stable across $\sigma_q$. Interpolated
to QASPER's observed $|\rho|{=}0.38$, a \emph{clean} linear signal of that strength
wins about half the splits ($54\%/49\%/49\%$ at $\sigma_q{=}0.15/0.25/0.35$); QASPER
wins only $14\%$. Since the synthetic model is perfectly specified, its win-rates
\emph{upper-bound} what is achievable at a given correlation, so QASPER's
$\approx 35$-point shortfall means its $-0.38$ correlation is \emph{not} a clean,
monotone, exploitable relationship---it is noisier / non-linear / outlier-driven
than the raw number suggests. The bottleneck is therefore the feature signal
itself, not label noise: a reliable win ($\ge 80\%$) requires $|\rho|\gtrsim 0.6$,
far beyond any of our six cheap features. This is corroborating, model-dependent
evidence; the positive control is assumption-light.

\section{Beyond Surface Density: Locality Features and a Target Diagnostic}
\label{sec:locality}

The power analysis sets a clear bar---a reliable win needs $|\rho|\gtrsim 0.6$, far
above the surface features' $0.38$. A natural rescue is that we simply used the
\emph{wrong} features: perhaps optimal leaf size is set not by surface lexical
density but by a document's intrinsic \emph{semantic-segment size / evidence
locality}. We test this directly, staying within the same cheap, no-LLM,
document-intrinsic envelope (SBERT sentence embeddings are already computed by the
harness).

\paragraph{Causally-motivated features.} We add three families: \emph{(A)
semantic-coherence} features from adjacent-sentence cosine similarities---mean and
variance of adjacent cosine, topic-shift rate (TextTiling-style boundaries per
$1$k tokens), \emph{mean semantic-segment length} (a direct training-free estimate
of the document's natural chunk size), and segment-length CV; \emph{(B) paragraph-
length distribution} (author-intended units); and \emph{(C) gzip compressibility}
(a model-free redundancy proxy). The mean semantic-segment length is the headline
candidate: it is, almost by definition, an estimate of the right scale for a leaf.

\paragraph{They also fail---and by more than surface density.}
Table~\ref{tab:locality} reports the per-feature Spearman against $\hat S(d)$. The
strongest is gzip compressibility at $|\rho|=0.249$; the headline semantic-segment
length is essentially zero ($-0.067$). \emph{Every} locality feature correlates
\emph{less} with optimal size than the surface \texttt{type\_token\_ratio}
($0.379$) did, and all are far below the $0.6$ bar. Used to size leaves over the
same $50$ held-out splits, the selected locality feature scores $0.7098$ vs.\
$0.7291$ for the tuned fixed size and wins only $10/50$ splits ($20\%$)---the same
loss pattern as H2.

\paragraph{The target diagnostic: the chain breaks at the optimum, not the
features.} The decisive evidence is the last row of Table~\ref{tab:locality}. We
compute a \emph{label-derived} feature---the mean token length of a question's
gold-evidence paragraphs (E2), the quantity we hypothesized \emph{is} the optimal
leaf size---and correlate it with $\hat S(d)$. It is essentially zero
($\rho=0.005$). This is stronger than ``we lack a good cheap feature'': it shows
the \emph{target itself does not respond} to the mechanism we theorized. Note the
chain: paragraph length \emph{does} predict E2 ($\rho=0.452$), so the features
\emph{can} see evidence geometry---but E2 does not predict optimal size, so
document structure simply does not determine the best leaf size in this pipeline.
Because even a near-oracle, label-derived signal is uncorrelated with the optimum,
no document-intrinsic feature can succeed, and \emph{scaling $N$ cannot help}
(more samples cannot recover a correlation the mechanism does not produce).

\paragraph{Robust to the flat-curve confound.} E1 finds $22\%$ of documents are
size-insensitive (a near-flat oracle curve), which could dilute correlations.
Restricting to the $39$ size-sensitive documents---the most favorable stratum---does
not rescue the route: E2 is still $-0.032$, the best feature reaches only $0.258$,
and the selected-feature map still loses ($0.7095$ vs.\ $0.7164$ fixed; win-rate
$36\%$). Even where leaf size demonstrably matters, no cheap feature predicts the
optimum.

\section{Structure-Axis Control: No Harm on Unstructured Text}
\label{sec:control}

On QuALITY (plain narrative prose; multiple-choice), AHC and the token baseline
are a statistical tie ($0.400$ vs.\ $0.381$ accuracy over $105$ paired questions;
overlapping $95\%$ CIs). The cause is mechanical and intended: the
structure-routing rate is $0.0000$---no document has exploitable structure, so AHC
falls back to token chunking everywhere and runs the same chunker as the baseline.
QuALITY thus serves as an \emph{unstructured control}: the structure axis does no
harm when there is nothing to exploit. The structure path is genuinely exercised
only on structured corpora (QASPER); that end-to-end run is in progress.

% ----------------------------------------------------------------------------
\section{Generality: A Second Corpus}
\label{sec:generality}

A single-corpus refutation invites the objection that QASPER scientific papers are
special. We therefore repeat the analysis on \textbf{QuALITY} (long narrative
passages, multiple-choice), a deliberately different genre. QuALITY ships no
gold-evidence spans, so we generalize the proxy to \emph{answer recall}: the best
token-recall of the gold answer (the correct option text) within the retrieved
context, with the per-document optimal size defined as before. The proxy is
non-degenerate (mean answer-recall $0.620$; median document length $4685$ tokens,
so leaf size is a real choice).

\paragraph{Headroom is smaller, and the negative replicates.} On $30$ QuALITY
articles ($448$ scored questions) the best fixed size is $400$ tokens at coverage
$0.6227$; the per-document oracle reaches $0.6414$---only $+3.0\%$ relative
headroom (vs.\ $+9.8\%$ on QASPER). The strongest single feature reaches
$|\rho|=0.40$ (\texttt{nonstopword\_ratio} $+0.396$,
\texttt{mean\_segment\_len\_tokens} $-0.396$, \texttt{topic\_shift\_rate}
$+0.379$), still below the $0.5$ bar. Over $50$ held-out splits the selected
feature scores $0.6260$ vs.\ $0.6268$ for the tuned fixed size and wins $26/50$
($52\%$)---a coin flip. The cheap-feature policy is therefore \emph{non-inferior
but not better}: it does not beat a tuned global size on either corpus.

\paragraph{A cross-corpus nuance.} The semantic-locality features carry
\emph{more} signal on narrative prose than on scientific papers
(\texttt{mean\_segment\_len\_tokens} $-0.396$ on QuALITY vs.\ $-0.067$ on QASPER;
\texttt{topic\_shift\_rate} $+0.379$ vs.\ $+0.089$), consistent with semantic
segments being a more meaningful unit in narrative text---yet the correlation
still tops out near $0.40$, and the small headroom means even the oracle barely
beats fixed. The qualitative conclusion is unchanged across two very different
corpora.

\section{Where the Headroom Lives: A Nested-Oracle Decomposition}
\label{sec:headroom}

H2 shows that no \emph{document-intrinsic} feature predicts the optimal leaf size,
but leaves open \emph{where} the oracle headroom actually resides. We answer this
directly with a nested-oracle decomposition run at \textbf{full scale}---the entire
QASPER \texttt{test} split ($416$ papers, $1{,}451$ answerable questions, $1{,}352$
scored question units, $8\times$ the $N{=}50$ H1/H2 cohort). We define five oracles,
each allowed to choose one leaf size per \emph{group}, from coarsest to finest:
$O_0$ one global size; $O_1$ one size per document; $O_2$ one per query type
(evidence multiplicity $m$, the number of gold-evidence paragraphs); $O_3$ one per
(document $\times$ type); and $O_4$ one per individual question (the absolute
ceiling). To remove the optimism of an oracle that tunes and scores on the same
data, we reuse \emph{the H2 held-out protocol}: fit each oracle's per-group argmax
size on a random $70\%$ of questions and score on the disjoint $30\%$, over $50$
splits (mean and $95\%$ band). All rungs are scored on the same held-out set, so the
gaps telescope into additive, separately-named components:
$\mathrm{document}=O_1-O_0$, $\mathrm{query\text{-}type}=O_2-O_0$,
$\mathrm{interaction}=O_3-O_1-O_2+O_0$, and $\mathrm{within\text{-}doc}=O_4-O_3$,
which sum to $\mathrm{total}=O_4-O_0$. ($O_4$ is a per-question ceiling---a held-out
question was never fit, so it is scored as the in-sample best-of-sizes, making
$\mathrm{within\text{-}doc}$ a conservative \emph{upper bound}.)

\paragraph{Held-out, the document component is negative.} In-sample the
per-document oracle looks strong ($O_1=0.824$, a $+0.065$ document component), but
that is overfitting: with only $\approx 3.3$ questions per QASPER paper, a size fit
on a document's train questions and applied to its held-out questions gives
$O_1=0.712$---\emph{below} the global $O_0=0.756$ ($-5.8\%$ rel.; the gap's $95\%$
band $[-0.060,-0.028]$ excludes $0$). The $0.11$-point swing between in-sample and
held-out \emph{is} the optimism removed. Because $O_1$ is the ceiling of any
per-document-\emph{feature} policy, this is stronger than H2: not only does no
document feature predict the optimum, the entire per-document adaptation family is
\emph{dominated} by a single tuned size out-of-sample. The query-type component is
flat ($-0.002$, band spans $0$).

\paragraph{The headroom is within-question.} The per-question ceiling clears the
global size by $+0.090$ absolute ($+12\%$ rel.), and essentially all of it is
\emph{within-document}: $O_4-O_3=+0.115$ and $O_4-O_1=+0.135$, both with bands well
clear of $0$. A per-document feature emits one number per document and therefore
\emph{cannot} produce different sizes for different questions of the same document;
$\mathrm{within\text{-}doc}$ is a hard ceiling it can never reach. The H2 negative
result is thus \emph{structural}, not incidental: the exploitable signal lives at a
granularity---the individual question---that document-intrinsic features cannot
address by construction.

\paragraph{The aggregation axis.} Stratifying by evidence multiplicity $m$ (a
lookup-vs-aggregation axis)\todo{cite SLIDERS, arXiv:2604.22294 --- verify id}
sharpens the picture. Global-size coverage falls monotonically as questions demand
more evidence---$0.83 \to 0.75 \to 0.70$ from single-paragraph ($m{=}1$) to
aggregation ($m{\ge}3$) questions, a direct measurement (not an oracle)---so
aggregation is retrieval-hard independent of any tuning. Meanwhile the
within-document headroom grows with $m$ ($0.004 \to 0.010 \to 0.019$, in-sample and
hence conservative). The headroom concentrates precisely where retrieval is hardest
and a single leaf size is least adequate, pointing past leaf-size tuning toward
query-aware, structured-extraction approaches for aggregation questions.

\section{Discussion}
\label{sec:discussion}

\paragraph{What we refute.} On QASPER, per-document leaf-size heterogeneity
creates real oracle headroom ($+9.8\%$ rel.), but cheap, training-free density
features---and a learned regressor on them---do not predict per-document optimal
leaf size well enough to beat a single tuned global fixed size. The popular
``smaller chunks for denser text'' heuristic is not supported at this granularity
for hierarchical-RAG leaves. The refutation is broader than the surface features:
\emph{causally-motivated} semantic-locality features fail too
(Section~\ref{sec:locality}), and a label-derived diagnostic shows the optimum is
uncorrelated with gold-evidence span length. The honest conclusion is therefore
not ``these features are weak'' but ``per-document optimal leaf size is not an
exploitable function of any document-intrinsic property we measured.''

\paragraph{Practical takeaway.} Tune \emph{one} global leaf size ($\approx 200$
tokens here); it is a strong, hard-to-beat baseline. Per-document density-based
leaf sizing is not worth its complexity without a better signal than closed-form
surface density.

\paragraph{Where a win could still live.} The headroom is real and unclaimed: the
oracle leaves $\approx 0.10$ coverage above every predictor we tried. The
nested-oracle decomposition (Section~\ref{sec:headroom},
Table~\ref{tab:headroom}) now localizes it \emph{directly}, no longer by
inference: held out at full scale, a per-document oracle actually
\emph{underperforms} one global size ($\mathrm{document}=-0.045$), while almost all
the headroom is \emph{within-document / per-question} ($O_4-O_1=+0.135$)---a
granularity a one-number-per-document feature cannot reach by construction, and one
that concentrates in multi-evidence aggregation questions. This is exactly the
\emph{query-aware / retrieval-dependent} signal we anticipated: the residual is set
by the question, not the document alone. It is the \emph{learned, query-aware}
territory of \cite{mog2024,hichunk2025}, which abandons the cheap training-free,
document-intrinsic differentiator we set out to test and is a substantially larger
project. We refute exactly that intended contribution---cheap, closed-form,
training-free, document-intrinsic leaf sizing---and point future work at the
query-aware route.

% ----------------------------------------------------------------------------
\section{Threats to Validity}
\label{sec:threats}

\textbf{Proxy gap.} Gold-evidence token-coverage (retrieval) is not end-task QA;
results are arm-vs-arm. \textbf{Scale / corpus.} The H1/H2 correlation results are $N{=}50$ on QASPER; CIs
are wide (std $\approx 0.04$). The headroom decomposition
(Section~\ref{sec:headroom}), however, is run on the \emph{full} QASPER
\texttt{test} split ($416$ papers, $1{,}352$ question units) with held-out $95\%$
bands, so the central where-does-the-headroom-live conclusion---and the sharper
finding that a per-document oracle loses to a global size out-of-sample---does not
rest on the small cohort. The negative conclusion is robust \emph{for the cheap,
document-intrinsic route} on three independent grounds: the learned ceiling on the
surface features fails, the causally-motivated locality features fail, and even a
label-derived (near-oracle) target diagnostic is uncorrelated with the optimum---so
the failure is pinned to the target, not to a particular feature or to label
noise. The single-corpus concern is addressed by the QuALITY replication
(Section~\ref{sec:generality}), though that rests on a weaker answer-recall proxy
and a near-parity margin, so it is a \emph{non-inferiority} generalization rather
than a second decisive refutation. \textbf{Proxy on the second corpus.} QuALITY's
answer-recall (correct-option text recalled in context) is noisier than QASPER's
gold-evidence coverage, since options are often paraphrases; we report it as
directional. \textbf{Untested.} We do not test \emph{query-aware / learned
multi-signal} predictors, where a win may still live. \textbf{Free-tier nondeterminism.} Clustering and LLM steps are not
bit-exact; we report variance and cache all LLM calls. \textbf{Fixed
embedder/reader.} Within-pipeline numbers only.

% ----------------------------------------------------------------------------
\section{Conclusion}
\label{sec:conclusion}

We built a training-free, no-LLM harness for studying leaf granularity in
hierarchical RAG and used it to show that, while per-document optimal leaf size is
heterogeneous and leaves real oracle headroom (H1), cheap deterministic density
features cannot capture it (H2)---a tuned global fixed size wins, and a learned
regressor on the same features does not change that. Pushing further, neither
causally-motivated semantic-locality features nor a label-derived target
diagnostic predict the optimum, so the negative result is not about a particular
feature set: per-document optimal leaf size is simply not an exploitable function
of any document-intrinsic property we measured, which redirects the search toward
query-aware signals. We report this as an honest, reproducible refutation of a
common-but-unvalidated chunking heuristic, and we release the harness so that
richer per-document granularity predictors can be evaluated against the same
oracle.
