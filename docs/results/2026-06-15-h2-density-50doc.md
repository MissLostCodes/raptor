# H2 Result — density features vs optimal leaf size (50-doc QASPER run)

**Date:** 2026-06-15 · **Branch:** `ckraptor` · **Status:** FINAL (n=50) — **H2 gate FAILED → pivot to negative result**
**Inputs:** the scaled 50-doc granularity sweep (`notebooks/granularity_calibration.ipynb`,
run on Colab T4, resumed from the Drive-cached `granularity_sweep_50.json`) + deterministic
`density_score` features. SBERT only for the sweep coverage proxy; **no LLM anywhere**.
300 `(doc, size)` records over `SIZES = {50,100,150,200,300,400}`, 2000-token budget,
50 QASPER papers / 171 answerable (gold-evidence) questions.

## TL;DR

**H1 replicates and holds: there is real per-document headroom** — the per-doc oracle beats
the best single fixed size by **+9.8% relative** coverage. **H2 fails decisively: cheap
training-free density features do not capture that headroom.** Used to size leaves, the
selected-feature map **loses to a tuned global fixed size** (0.704 vs 0.729 mean TEST
coverage; beats fixed in only **7/50** splits). A **learned 6-feature regressor also loses**
(0.707) — so the bottleneck is the *feature set*, not the closed-form mapping. The strong
features from the n=8 preview were small-N overfitting and **collapsed** at n=50. Per the
spec decision gate, we pivot to the honest "a well-chosen fixed leaf size is enough"
negative result.

## H1 — size matters & is heterogeneous (PASS)

- **Headroom (Fig.1).** best fixed size = **200 tok @ cov 0.7362**; per-doc **oracle cov
  0.8080**; `abs_gap = 0.0718` (**+9.8% rel.**). The oracle sits well above the best fixed
  point → genuine adaptive headroom *exists*.
- **Heterogeneity.** Per-doc optimal-size distribution over 50 docs:
  `{50: 17, 100: 11, 150: 6, 200: 8, 300: 3, 400: 5}` — mass at every size, mode at 50.
  Consistent with the 8-doc pilot (optimum spans 50→400).

H1 is the *premise*, not the contribution; it survives at scale.

## H2 — cheap features predict optimal size (FAIL)

### Spearman of each density signal vs per-doc optimal size (feature ablation)

| signal | n=50 | (n=8 preview) |
|---|---:|---:|
| `type_token_ratio` | **−0.379** | −0.602 |
| `nonstopword_ratio` | +0.158 | +0.663 |
| `numeral_symbol_density` | +0.153 | −0.258 (sign flip) |
| `mean_word_len_chars_norm` | +0.108 | +0.786 |
| `mean_sentence_len_tokens_norm` | −0.080 | +0.025 |
| `list_marker_density` | +0.061 | 0.000 |
| `rho` (equal-weight composite) | −0.147 | +0.037 |

**The preview's optimism was overfitting.** The two features that looked strongest at n=8
(`mean_word_len` +0.79, `nonstopword_ratio` +0.66) collapsed to +0.11 / +0.16 at n=50;
`numeral_symbol_density` even flipped sign. Only `type_token_ratio` survives with any
magnitude (−0.38) — moderate at best, and, as the held-out eval shows, too weak to be
useful.

### Held-out evaluation — single 70/30 split (illustrative; 35 train / 15 test)

selected feature: `type_token_ratio` (train corr −0.399)

| policy (TEST docs) | mean coverage |
|---|---:|
| best global fixed (200 tok) | **0.7375** |
| training-free: composite `rho`→size | 0.6608 |
| training-free: `type_token_ratio`→size | 0.6773 |
| learned regressor (sklearn, 6 feat) | 0.6615 |
| per-doc oracle (ceiling) | 0.7806 |

Every adaptive/learned policy lands **below** the fixed baseline on this split.

### Held-out robustness — 50 random 70/30 splits (the headline H2 statistic)

| policy | mean | std |
|---|---:|---:|
| best global fixed | **0.7291** | 0.0433 |
| training-free: composite `rho` | 0.7212 | 0.0447 |
| training-free: selected feature | 0.7037 | 0.0494 |
| learned (6 feat) | 0.7071 | 0.0415 |
| per-doc oracle | 0.8061 | 0.0347 |

- selected-feature map beats best-global-fixed in **7/50 splits (14%)**.
- selected-feature stability: `{type_token_ratio: 47, mean_sentence_len: 1, mean_word_len: 1, nonstopword_ratio: 1}` → feature choice is **stable**.

## Verdict against the documented H2 gate

The spec gate (`docs/specs/2026-06-11-density-adaptive-chunking.md` L172–178) requires the
selected-feature closed-form map to **(i)** beat best-global-fixed at a high win-rate,
**(ii)** with a stable selected feature, and **(iii)** approach the learned regressor *and*
the per-doc oracle.

| Criterion | Result | |
|---|---|:--:|
| (i) high win-rate over best-global-fixed | 14% (7/50); mean 0.704 < 0.729 | ❌ |
| (ii) stable selected feature | `type_token_ratio` 47/50 | ✅ |
| (iii) approaches learned **and** oracle | ≈ learned (0.704 ≈ 0.707) but both lose to fixed; vs oracle 0.704 vs 0.806 (≈ all headroom unrealized) | ❌ |

**Only (ii) is met. H2 GATE: FAILED.** A stable predictor that reliably loses to a fixed
baseline is just stably weak. The decisive point: **the learned regressor also fails**, so
no amount of model sophistication on this feature set converts the oracle headroom into a
win — the cheap density features simply don't carry the granularity signal.

## What this means (the negative result)

> On QASPER, per-document leaf-size heterogeneity creates real oracle headroom (+9.8% rel.
> gold-evidence coverage), but **cheap, training-free density features — and a learned
> regressor on them — fail to predict per-document optimal leaf size well enough to beat a
> single tuned global fixed size.** The widely-repeated "smaller chunks for denser text"
> heuristic is **not supported** at this granularity for hierarchical-RAG leaves.

**Practical takeaway:** tune one global leaf size (≈200 tok here) — it is a strong,
hard-to-beat baseline. Per-document density-based leaf sizing is not worth its complexity
without a *better signal* than closed-form surface density.

## Honesty / limits

- **Within-pipeline, proxy metric.** Fixed SBERT embedder (`multi-qa-mpnet-base-cos-v1`)
  + gold-evidence token-coverage proxy (≥0.8 recall), not end-task QA. Arm-vs-arm, not
  leaderboard numbers.
- **N=50, single corpus** (QASPER scientific papers); wide CIs (std ≈ 0.04). The negative
  conclusion is robust to this N *for the cheap-density route* precisely because the
  learned upper bound on the same features also fails — but it does **not** generalize to
  other document types or to *richer / query-aware* signals.
- **The headroom is real and unclaimed.** The oracle (0.806) leaves ~0.10 coverage on the
  table above every predictor we tried. A better predictor (e.g., learned multi-signal /
  query-adaptive, à la Mix-of-Granularity / HiChunk) could still win — we only refute the
  *cheap, closed-form, training-free density-feature* route, which was the project's
  intended contribution.

## Decision (per spec L176–178)

- **Do NOT** inject `(feature, a, b)` into `ExperimentConfig.density_*`.
- **Do NOT** run E3 (expensive LLM end-to-end) for the density arm — it is gated off.
- **Pivot** to the negative result, carried by the H1 headroom (Fig.1) + the cheap SBERT
  proxy, exactly as the spec anticipated. The `DensityAdaptiveChunker` mechanism remains in
  the tree (unit-tested) but is not a reported arm.

## Paper reframe (negative / cautionary contribution)

1. A reusable **training-free, no-LLM harness** to study leaf granularity in hierarchical
   RAG: oracle leaf-size sweep + gold-evidence coverage proxy (resumable, Colab-cached).
2. **H1 evidence:** per-document optimal leaf size is heterogeneous with substantial oracle
   headroom.
3. **H2 negative result:** cheap deterministic density features (and a learned regressor on
   them) do **not** capture that headroom — a tuned global fixed size wins. A rigorous,
   first formalization+refutation of the common-but-unvalidated "adaptive density" heuristic.
